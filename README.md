# Dictation Daily user guide

The help centre for [Dictation Daily](https://dictationdaily.com), published with GitHub Pages:
**https://docs.dictationdaily.com/** (GitHub Pages with a custom domain; https://dictationdaily.github.io/ redirects there)

A friendly, step-by-step help site for learners, styled with Tailwind CSS. Pages are short and task-based,
written in simple English, with scroll steps over real screenshots (no Back/Next buttons: the picture
follows the step you are reading), looping screen recordings of the app, search (`/` or `Ctrl K`), a filterable FAQ and dark mode. `build.mjs` wraps each page in one layout.

## Layout

| Path | What |
|---|---|
| `src/pages/<slug>.html` | Page content. Starts with `<!-- {"title": …, "description": …, "time": …} -->`. Can use `<tour>`/`<step>`, `<demo>` and `<shot>` (see `build.mjs`) |
| `src/coords.json` | Measured button positions in the lesson shots, used by `<step at="…">` (written by `scripts/capture.py`) |
| `src/nav.json` | Sidebar groups, page icons and order (also sets the Next card) |
| `src/layout.html` | Header, sidebar, contents column, footer, search and lightbox |
| `src/input.css` | Tailwind entry and the content components (`callout`, `figure`, `steps`, `faq`, …) |
| `assets/site.js` | Scroll steps, recordings, scroll animations, search, theme, drawer, lightbox, FAQ filter |
| `build.mjs` | Writes `_site/`: pages, `search-index.json`, `sitemap.xml`, `robots.txt` |
| `images/` | Screenshots (WebP) |
| `videos/` | Screen recordings (`.mp4`) and their posters (`.jpg`) |

To add a page: create `src/pages/<slug>.html` and add it to `src/nav.json`.

## Develop

```bash
npm install
npm run build          # CSS + pages into _site/
npm run serve          # http://localhost:8000
npm run dev            # in another terminal: rebuild CSS on change (rerun build:pages after editing pages)
```

Pushing to `main` builds and deploys the site (`.github/workflows/pages.yml`).

## Screenshots

Signed-out screenshots are taken by `scripts/capture.py` with Playwright and Chrome, from production or, with `DD_BASE`, from a local build of the app (for a UI change that isn't deployed yet: in the app repo build, pre-render and run `tests/e2e/local_worker.sh`). It never signs in, so it saves nothing:

```bash
pip install playwright pillow
python3 scripts/capture.py images            # or: --only library lesson-hint (exact shot names)
DD_BASE=http://localhost:8788 python3 scripts/capture.py images --only lesson-hint
python3 scripts/to_webp.py                   # also writes the crop-* hint close-ups
```

The signed-in language shots (`lesson-translation`, `welcome-speak`, `settings-languages`) were taken on a local build with the Demo Learner (mother tongue Vietnamese) after copying the French lesson `YCuU4SjcS2A` and its `translations/vi.json` from production into local R2 (public at `/transcripts/<id>.json` and `/translations/<id>/vi.json`). The language shots (`home-languages`, `welcome-learn`, `library-language-menu`, `library-french`, `lesson-fr-*`: Easy French 97, `YCuU4SjcS2A`) and `word-card` / `mobile-word-card` come from the same script. The YouTube settings shots (`youtube-settings`, `youtube-speed-menu`, `youtube-player`, cropped to the player) were captured by hand in the same way and cropped.
The signed-in shots (`account-menu`, `signed-in-library`, `my-videos`, `my-learning`, `lesson-resumed`, `lesson-finished-streak`), plus `lesson-finished`, `lesson-no-transcript`, `not-found`, `my-learning-signed-out` and the hand-captured `google-signin`, come from the app repo's `docs/user/images/` (generated by `tests/e2e/docs_screenshots.py` with the *Demo Learner* account). `my-learning` and `my-learning-more` are the top and bottom 900 px of its full-page `my-learning.png`. Never use screenshots that show a real learner's name, email or avatar. **Show the Pro view.** Since 2026-11-03 every lesson shot, every signed-in page and all six recordings are taken on production as a Pro learner, so lesson controls are visible without sign-in prompts. All signed-in plans now have the same features; the free plan has a daily time allowance and Pro has unlimited practice. Set `DD_SESSION` to a file holding a Pro account's `__Secure-authjs.session-token` cookie value (never commit it); `scripts/pro_session.py` then signs the browser in read-only: every write is answered locally (progress, activity, Shadowing place, goal, languages, waitlist, word reports, visit log, bug reports, voice checks), every lesson looks unstarted so scripts begin at sentence 1, and the account's name, email and picture become *Demo Learner*, demo@example.com and a "D" avatar. Home, library and welcome shots stay as a visitor sees them. Do not embed the obsolete `shadowing-pro` or `word-card-free` shots: they show the retired feature paywalls. Explain the shared daily allowance in both languages instead.

```bash
export DD_SESSION=/path/to/cookie.txt
python3 scripts/capture.py images                        # lesson shots as Pro, the rest signed out
python3 scripts/capture_signed_in.py https://dictationdaily.com images   # library, My videos, My progress, Settings, gear, bug report, Shadowing, finish screens
python3 scripts/record.py                                # recordings as Pro
python3 scripts/to_webp.py && python3 scripts/boxes.py
```

`capture_signed_in.py` writes `my-learning` as the whole page: cut it into `my-learning` (top 900 px) and `my-learning-more` (bottom 900 px). It makes no paid call, except that a lesson without a translation in the account's language orders one (OpenAI, under a cent). The voice-answer shots (`dictation-mic`, `dictation-mic-correct`, say-your-answer.html) come from `scripts/capture_pro.py`: a local build with the Demo Learner set to Pro (`UPDATE users SET plan='pro' WHERE email='demo@example.com'` in the local D1) and a minted session cookie; nothing is recorded, the microphone is only shown.

A local build has transcripts for only a few videos, and few videos have a level or speed there. With `DD_BASE` set, `lesson-listen` and the `listen` scene use `-BvcToPZCLI` (it opens with a "Just listen" part), and `library-card` is the first card of *Slowest speaker first* (so it shows a level and a speed). `capture.py` keeps entries of `src/coords.json` it doesn't measure (for example the hand-placed `lesson-resumed`).

## Screen recordings

Every page leads with a recording (since 2026-11-03): `<watch src="voice" title="…"></watch>` (add `phone` for a phone one) shows `videos/voice.mp4` with its steps beside it, which light up and fill as the video plays; clicking a step plays from there. The steps are the captions the recording shows, saved with their times in `videos/<scene>.json` by `scripts/record.py`, so a new recording brings its own steps. Pages keep text short: the description, the recording, at most three cards, and collapsed questions.

```bash
export DD_SESSION=/path/to/cookie.txt     # a Pro account (see Screenshots): every scene as a Pro learner
python3 scripts/record.py                 # all scenes
python3 scripts/record.py voice shadow    # some
```

Scenes: `lesson`, `hints`, `library`, `speed`, `navigate`, `listen`, `mobile`, and the Pro ones `translation`, `word`, `voice`, `shadow`, `resume`, `streak`, `report`. In the Pro scenes the speech checks (`voice-answer`, `shadow-check`, `word-check`) are answered in the browser with a canned result, and the microphone is Chrome's fake device fed a voice-like tone, so a recording makes no paid call; the interface filmed is the real one. `DD_DEBUG=<dir>` saves a screenshot when a scene breaks.

The look is Cap's: `scripts/cap_render.py` draws a big pointer, a red ring on each click and the captions over the frames, and zooms in gently (1.35×, 1.2× on a phone, where it stays centred across) towards whatever is clicked, typed into (`type_()`) or pointed at (`look()`). It doesn't overuse the zoom: once in, it stays in and glides to the next action while that is close by and comes within 5 s, and skips a zoom-out shorter than 1.5 s; it zooms out only when the next action is far away, after a pause, or at the end. Each take (frames + event log) is kept in `~/.cache/dd-guide/takes/`, so `python3 scripts/record.py --render [scene …]` redraws the videos with new settings without recording again. `record.py` logs those events while Chrome's screencast saves the frames; nothing is drawn into the page itself. Captions use Nunito (downloaded once to `~/.cache/dd-guide/Nunito.ttf`, DejaVu Sans if missing).

## Vietnamese (`/vi/`)

The whole guide is also in Vietnamese at https://docs.dictationdaily.com/vi/ (since 2026-11-05). The flag in the header opens a menu of both languages by flag (English 🇬🇧, Tiếng Việt 🇻🇳, images from the app's `public/flags`); each opens the same page and section in the other language, and every page carries `hreflang` links.

- Pages: `src/vi/pages/<slug>.html`, the same slugs and HTML as `src/pages/` with the text translated. `<h2>`s keep the English anchor as `id="…"`, so `#links` work in both. The app's buttons stay in English (**START**, **CHECK**…), as learners see them on screen.
- Sidebar: `src/vi/nav.json`. Layout words (header, footer, search, Next card): `src/strings.json`, one block per language; `assets/site.js` has its few words in `WORDS`.
- Recordings: `videos/vi/<scene>.mp4|jpg|json` are the same takes with Vietnamese captions, from `scripts/captions.vi.json` (English caption → Vietnamese): `python3 scripts/record.py --render --lang vi [scene …]`. After recording a scene again, add any new caption to that file (the render stops on a missing one) and redraw it. A page whose scene has no Vietnamese video uses the English one.
- Headings: Fredoka has no Vietnamese letters (ữ ạ ầ fell back to a serif face), so Vietnamese pages use Baloo 2 (weight 800 for big headings) through `--font-display` in `src/input.css`.
- Search is per language (`vi/search-index.json`) and ignores accents (“toc do” finds “tốc độ”).
- When an English page changes, change its Vietnamese page in the same PR.

## Keeping it accurate

Behaviour described here was checked against the app's code and the live site. When the app changes, update the matching page, and the FAQ if a question is affected.
