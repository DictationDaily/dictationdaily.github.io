# Dictation Daily user guide

The help centre for [Dictation Daily](https://dictationdaily.com), published with GitHub Pages:
**https://dictationdaily.github.io/**

A friendly, step-by-step help site for learners, styled with Tailwind CSS. Pages are short and task-based,
written in simple English, with click-through tours over real screenshots, looping screen recordings of
the live app, search (`/` or `Ctrl K`), a filterable FAQ and dark mode. `build.mjs` wraps each page in one layout.

## Layout

| Path | What |
|---|---|
| `src/pages/<slug>.html` | Page content. Starts with `<!-- {"title": …, "description": …, "time": …} -->`. Can use `<tour>`/`<step>`, `<demo>` and `<shot>` (see `build.mjs`) |
| `src/nav.json` | Sidebar groups, page icons and order (also sets the Next card) |
| `src/layout.html` | Header, sidebar, contents column, footer, search and lightbox |
| `src/input.css` | Tailwind entry and the content components (`callout`, `figure`, `steps`, `faq`, …) |
| `assets/site.js` | Tours, recordings, scroll animations, search, theme, drawer, tabs, lightbox, FAQ filter |
| `build.mjs` | Writes `_site/`: pages, `search-index.json`, `sitemap.xml`, `robots.txt` |
| `images/` | Screenshots (WebP) |
| `videos/` | Screen recordings (`.mp4`) and their posters (`.jpg`) |

To add a page: create `src/pages/<slug>.html` and add it to `src/nav.json`.

## Develop

```bash
npm install
npm run build          # CSS + pages into _site/
npm run serve          # http://localhost:8000
npm run dev            # in another terminal: rebuild CSS on change (rerun build:pages after editing pages)
```

Pushing to `main` builds and deploys the site (`.github/workflows/pages.yml`).

## Screenshots

Signed-out screenshots come from production, taken by `scripts/capture.py` with Playwright and Chrome. It never signs in, so it saves nothing:

```bash
pip install playwright pillow
python3 scripts/capture.py images            # or: --only library lesson-hint
python3 scripts/to_webp.py
```

The YouTube settings shots (`youtube-settings`, `youtube-speed-menu`, `youtube-player`, cropped to the player) and `lesson-listen`/`lesson-hint-extra` were captured by hand in the same way and cropped.
The signed-in shots (`account-menu`, `signed-in-library`, `my-learning*`, `lesson-resumed`), plus `lesson-finished`, `lesson-no-transcript`, `not-found` and the hand-captured `google-signin`, come from the app repo's `docs/user/images/` (generated by `tests/e2e/docs_screenshots.py` with the *Demo Learner* account). Never use screenshots that show a real learner's name, email or avatar.

## Screen recordings

`scripts/record.py` records the live app (signed out) with a visible pointer and step captions, and encodes `videos/<scene>.mp4` with ffmpeg:

```bash
python3 scripts/record.py            # all scenes: lesson library speed navigate listen mobile
python3 scripts/record.py speed      # just one
```

Tour markers are positions in % of the screenshot. Measure them from the live app with Playwright's `bounding_box()` rather than guessing.

## Keeping it accurate

Behaviour described here was checked against the app's code and the live site. When the app changes, update the matching page, and the FAQ if a question is affected.
